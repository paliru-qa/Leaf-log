# LeafLog

Плант-трекер (українською). Дані зберігаються у спільній хмарній базі (Vercel KV), тож ними можна ділитись по лінку — доглядач, відкривши лінк, бачить актуальний список рослин і може відмічати полив/добриво.

## Структура

- `index.html` — весь фронтенд (без збірки)
- `api/plants.js` — серверна функція (Vercel Serverless Function), читає/пише дані у Vercel KV
- `package.json` — залежність `@vercel/kv`

## Розгортання на Vercel

1. Створи репозиторій на GitHub і залий туди всі файли з цієї теки.
2. Зайди на https://vercel.com/new і імпортуй репозиторій. Framework preset — "Other". Білд-команду залишити пустою.
3. Натисни Deploy (перший деплой ще без бази — це нормально, підключимо зараз).
4. У проєкті на Vercel відкрий вкладку **Storage** → **Create Database** → вибери **KV** (на базі Upstash Redis, безкоштовний тариф достатній).
5. Підключи створену базу до цього проєкту (Connect Project) — Vercel сам додасть потрібні env-змінні (`KV_REST_API_URL`, `KV_REST_API_TOKEN` тощо).
6. Зроби редеплой проєкту (Deployments → ... → Redeploy), щоб змінні підхопились.
7. Відкрий сайт — готово.

### Альтернатива через CLI
```bash
npm i -g vercel
cd leaflog
vercel                 # прив'язати проєкт, перший деплой
vercel storage create  # створити KV-базу і одразу підʼєднати до проєкту
vercel --prod           # задеплоїти в продакшн з підʼєднаною базою
```

## Як працює шеринг

- При першому відкритті сайту (без параметра в лінку) браузер генерує собі унікальний `householdId` і зберігає його в `localStorage`. Усі рослини читаються/пишуться в KV під цим id.
- Якщо в цей момент у браузері вже були старі дані (з попередньої, чисто локальної версії), вони автоматично переносяться в хмару при першому завантаженні.
- Кнопка **🔗 Поділитися** копіює лінк вигляду `https://твій-сайт.vercel.app/?h=<householdId>`.
- Той, хто відкриє цей лінк, автоматично потрапляє в **режим доглядача**: бачить ті самі рослини, може відмічати полив/добриво (це одразу зберігається в спільній базі), але не може додавати, редагувати чи видаляти рослини.

## Обмеження

- Посилання дає доступ будь-кому, хто його має (без пароля) — тому не публікуй його у відкритих місцях.
- Фото стискаються та зберігаються як base64 просто в записі KV, тому не варто додавати десятки великих фото — є практичні ліміти на розмір значення в KV (зазвичай кілька MB).
